Интерпретатор Structured Text (IEC 61131-3) на Python для тестирования
функциональных блоков CODESYS. Загружает исходники из `.st`-файлов,
циклически выполняет код и позволяет задавать входные значения и проверять
выходные. Для запуска тестов CODESYS и ПЛК не требуются.

Требуется Python 3.11+. Внешних зависимостей нет; для GUI нужен `tkinter`.

## Основные возможности

- **Загрузка проектов.** Можно загрузить отдельный файл, несколько файлов
  или папку со всеми вложенными `.st`-файлами. Блоки, функции,
  пользовательские типы данных (DUT), глобальные переменные и константы
  связываются в один проект. Применяются начальные значения полей DUT
  и глобальных переменных.
- **Особенности экспорта CODESYS.** Парсер принимает прагмы `{attribute ...}`,
  модификаторы `PUBLIC` / `FINAL` / `ABSTRACT`, объявления с адресами
  `AT %IX0.0`, анонимные перечисления и вложенные комментарии. Файл с блоком
  или функцией может заканчиваться без завершающего ключевого слова;
  незавершённые операторы при этом считаются ошибкой.
- **Конструкции и типы ST.** Поддерживаются `FUNCTION_BLOCK`, `FUNCTION`
  (включая рекурсию), `PROGRAM`, операторы `IF`, `CASE`, `FOR`, `WHILE`,
  `REPEAT`, `EXIT`, `CONTINUE` и `RETURN`. Доступны логические,
  целочисленные и вещественные типы, строки, даты и время,
  структуры, многомерные массивы, перечисления,
  `POINTER TO` и `REFERENCE TO`.
- **Стандартная библиотека.** Таймеры `TON`, `TOF`, `TP`, детекторы фронтов
  `R_TRIG`, `F_TRIG`, счётчики `CTU`, `CTD`, `CTUD`, блоки `RS`, `SR`,
  математические и строковые функции, преобразования типов. Блоки и функции
  из исходников проекта имеют приоритет перед одноимёнными встроенными.
- **Правила вычислений.** Переполнение целых обрабатывается с учётом
  разрядности типа; `REAL` хранится в формате float32. Округление при
  преобразовании в целое: `2.5 → 3`, `-2.5 → -3`. При целочисленном делении
  дробная часть отбрасывается, `MOD` сохраняет знак делимого. Для `BOOL`
  операторы `AND` / `OR` используют сокращённое вычисление, для целых
  те же операторы работают побитово. Деление на ноль вызывает ошибку.
- **Чтение и запись переменных.** Доступны поля вложенных блоков и структур,
  элементы массивов и отдельные биты: `travel.ET`, `Limits.Lo`,
  `Configs[2].Mode`, `Status.3`. Индексы проверяются по объявленным границам
  массива. Из Python можно передавать структуры словарями, массивы списками,
  время строками вроде `"200ms"`, а значения перечислений — по имени.
- **Тесты на Python.** `Testbench` задаёт значения и запускает нужное число
  циклов. Метод `expect()` сохраняет результаты проверок: ожидаемое
  и фактическое значения, номер цикла и виртуальное время. Несовпадение
  не прерывает тест; `failures` содержит список неудачных проверок,
  а `summary()` возвращает текстовый отчёт.
- **API для управления блоком.** Через `Session` можно выполнять код
  и работать с переменными без проверок ожидаемых значений. Методы
  `inputs()`, `outputs()` и `variable()` описывают интерфейс блока,
  `snapshot()` возвращает состояние: значения `TIME` представлены строками
  вида `T#2s`, значения перечислений — именами элементов.
  Функции ST можно вызывать напрямую через `call()`.
- **Командная строка.** `check` проверяет исходники без их выполнения,
  `vars` показывает входы и выходы с типами и элементами перечислений.
  Команды `run` и `scan` выполняют заданное число циклов. При запуске можно
  задать значения переменных, проверить результат или вывести состояние
  после каждого цикла.
- **Графический интерфейс.** Выбор папки проекта и блока, задание входных
  значений и наблюдение за выбранными выходами. Для `BOOL` используются
  флажки, для перечислений — списки, для структур и массивов — JSON.
  Можно выполнить один цикл, заданное число циклов или включить непрерывное
  выполнение. Сброс возвращает блок в начальное состояние, сохраняя
  настройки формы.
- **Диагностика.** Для ошибок в ST-коде указывается место в исходнике:
  `файл:строка:столбец`. При неверном значении сообщение подсказывает,
  например, допустимые имена полей, значения перечисления или границы массива.

## Как это работает

1. **Разбор и связывание.** Лексер и парсер строят дерево ST-кода.
   Типы, функции, блоки и глобальные переменные из загруженных файлов
   объединяются в модель проекта.
2. **Создание экземпляра.** Для выбранного блока создаётся экземпляр
   с начальными значениями переменных. Его состояние сохраняется между
   циклами. Параметры `VAR_IN_OUT` передаются по ссылке: изменения видны
   вызывающему коду.
3. **Выполнение цикла.** Тест задаёт входные значения, интерпретатор
   выполняет тело блока, затем тест читает переменные и проверяет результат.
   Командная строка, графический интерфейс и `Testbench` работают через
   общий API `Session`.
4. **Виртуальное время.** После каждого цикла время увеличивается
   на `cycle_time`. При `cycle_time="10ms"` 200 циклам соответствуют
   две секунды виртуального времени. Таймеры используют эти часы, поэтому
   при одинаковых входных значениях и последовательности циклов их результат
   не зависит от скорости компьютера. Ожидать в реальном времени не нужно.

Установка из корня репозитория:

```bash
python3 -m pip install -e .
```

### Анализ функционального блока

Проверка [ST-файла](examples/valve.st) без выполнения кода:

```console
$ python3 -m microtuss check examples/valve.st
ok: 1 POU(s), 38 type(s), 2 global(s)
  FUNCTION_BLOCK FB_VALVE
```

Просмотр входов, выходов и их типов; для перечислений выводятся имена элементов:

```console
$ python3 -m microtuss vars examples/valve.st
FB_VALVE (FUNCTION_BLOCK)
  inputs:
    CMD                  BOOL
    TRAVELTIME           TIME
  outputs:
    OPEN                 BOOL
    BUSY                 BOOL
    STATE                E_VALVESTATE  (CLOSED, OPEN)
```

Если блок использует типы и функции из других файлов, можно загрузить папку
проекта целиком и указать нужный блок через `--pou`:

```bash
python3 -m microtuss check examples/project/
python3 -m microtuss vars examples/project/ --pou FB_Tank
```

### Выполнение по циклам

Пример теста для блока из `examples/valve.st`:

```python
from microtuss import Testbench

tb = Testbench.from_file("examples/valve.st", "FB_Valve", cycle_time="10ms")
tb.scan(Cmd=True)                 # задать вход и выполнить один цикл
tb.run(200)                       # ещё 200 циклов: +2 с виртуального времени
tb.expect(Open=True, Busy=False)
print(tb.summary())
assert not tb.failures
```

Проверка выхода `Open` из командной строки:

```console
$ python3 -m microtuss run examples/valve.st --set Cmd=true --scans 201 --expect Open=true
FB_VALVE: 1/1 expectations passed
```

Запуск графического интерфейса:

```bash
python3 -m microtuss.gui examples/project/ FB_Tank
```

Аппаратный ввод-вывод не моделируется. Из расширений CODESYS не поддерживаются
`METHOD`, `PROPERTY`, `INTERFACE`, `CLASS`, `NAMESPACE` и `ACTION`.
Прагмы и модификаторы объявлений не влияют на выполнение;
сохранение переменных `RETAIN` / `PERSISTENT` между запусками не моделируется.
`UNION` обрабатывается как структура с независимыми полями, без общей
области памяти.
